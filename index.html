Concept 1: Hosted LLM APIs vs. Self-Hosted Open-Source Models

Status: 🟢 Understand the concept

What is it?

Choosing between renting an AI brain via external API (OpenAI/Gemini) vs. hosting a free, public model blueprint (Llama) on our own cloud infrastructure.

Why care as a DM?

APIs offer rapid time-to-market but carry variable Opex costs and external data privacy risks. Open-Source requires high upfront Capex and cloud expertise but guarantees data security and predictable infrastructure pricing.

Status: 🟡 Know how to configure or use it

What is it?

Writing technical and delivery documentation in lightweight formats (like Markdown/HTML) and managing it inside a Git repository alongside the codebase, utilizing automation to publish it live.

Concept 5: The 3-Tier Enterprise AI Architecture

Status: 🟢 Understand the concept

What is it?

A structural classification framework inside a Microsoft/Azure corporate environment that categorizes AI solutions into three tiers based on process complexity, data scale, and deployment governance.

  • Tier A (Agent Builder): Fast, built-in, low-friction bots running out of the box in M365 Copilot, using localized text files on SharePoint[cite: 1, 3].
  • Tier B (Copilot Studio): Fully managed workflow applications using Power Automate, proactive alerts, multi-step routing, and strict environment deployment pipes (ALM)[cite: 2, 3].
  • Tier C (Azure AI Foundry): High-capacity data services leveraging Azure OpenAI, AI Search, and Document Intelligence (OCR) to ingest heavy datasets or complex layouts[cite: 2, 3].

Concept 6: Deep Dive into Tier B Automation & Tier C Data Engines

Status: 🟢 Understand the concept

What is it?

The specific, underlying enterprise mechanics that allow an AI system to handle automatic cross-department business workflows (Tier B) and heavy unrefined data (Tier C)[cite: 2, 3].

  • Power Automate (Tier B): Programmatic trigger systems that replace manual human steps[cite: 2, 3]. It auto-detects dropped data files, awakens the AI agent, executes logical checks, and pushes results directly to teams[cite: 2, 3].
  • ALM Pipelines (Tier B): Automated deployment tracks separating code environments[cite: 2]. Code goes from safe Developer Playgrounds (Sandboxes) to explicit Test environments (UAT) for verification before moving to Production[cite: 2].
  • Document Intelligence (Tier C): Specialized Optical Character Recognition (OCR) engines used to parse grids, layouts, complex tables, and text structures from massive or scanned PDF documents[cite: 2, 3].
  • Azure AI Search (Tier C): High-scale vector data systems that slice large document archives into conceptual fragments, allowing models to search and pinpoint specific sections instantly[cite: 2, 3].

Why care as a DM?

  • Tier B requires environment planning: If the client’s platform administrators have not pre-approved tenant infrastructure settings, security permissions, and service connections, developers cannot ship code[cite: 2]. Access parameters represent critical path dependencies[cite: 2].
  • Tier C requires data sprint sizing: Parsing dense data isn't achieved by prompt tweaking; it requires data-engineering setups[cite: 3]. Sprints must isolate data-processing and indexing work early[cite: 2, 3].

Questions to Ask

  • "To the Tech Lead: Are our Tier B deployment pipelines (ALM) managed via Azure DevOps, or are developers manually importing solutions?"[cite: 2]
  • "To the Data Engineer: For table-heavy use cases, are we utilizing Azure Document Intelligence to isolate grids, or are we passing unstructured text directly to the model?"[cite: 2, 3]

Simple Analogy

Imagine transforming an enterprise Local Factory Operations Model:

  • Tier B (Automation & ALM) = Automated conveyor belts and inspection loops. Replaces manual carrying with systemic sensors. ALM ensures that before new equipment steps onto the manufacturing floor (Production), it undergoes rigorous stress runs in a replica testing bay (UAT)[cite: 2].
  • Tier C (Azure Foundry & OCR) = An extraction processing plant. Raw, dense mineral ores (scanned tables and 300-page booklets) cannot enter processing directly[cite: 3]. You need a dedicated extraction mill (Document Intelligence) to refine, sort, and tag contents first[cite: 2, 3].
