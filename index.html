AI Delivery Playbook

A living document tracking my execution and strategy as an AI Delivery Leader.

Concept 1: Hosted LLM APIs vs. Self-Hosted Open-Source Models

Status: 🟢 Understand the concept

What is it?

Choosing between renting an AI brain via external API (OpenAI/Gemini) vs. hosting a free, public model blueprint (Llama) on our own cloud infrastructure.

Why care as a DM?

APIs offer rapid time-to-market but carry variable Opex costs and external data privacy risks. Open-Source requires high upfront Capex and cloud expertise but guarantees data security and predictable infrastructure pricing.

Questions to Ask

  • What is our projected user volume, and where is the tipping point where hosting our own model becomes cheaper than API fees?
  • Does the client's compliance policy allow sending data to a third-party API?

Simple Analogy

APIs = Uber: Quick, no maintenance, but expensive if run 24/7.
Open Source = Owning commercial vans: High upfront cost and requires your own mechanics, but cheaper for heavy, constant usage.

Concept 2: Version-Controlled Documentation (Docs-as-Code)

Status: 🟡 Know how to configure or use it

What is it?

Writing technical and delivery documentation in lightweight formats (like Markdown/HTML) and managing it inside a Git repository alongside the codebase, utilizing automation to publish it live.

Why care as a DM?

Eliminates document fragmentation, builds a permanent audit trail of project decisions, and ensures the delivery playbook sits exactly where the engineering team works.

Concept 3: AI Agent Team Topology & Roles

Status: 🟢 Understand the concept

What is it?

The specialized staffing structure required to scale AI applications beyond basic software development. It introduces specific roles focused on cognitive architecture, data fuel, and non-deterministic testing.

Why care as a DM?

Staffing a modern AI project with a generic software engineering mix creates delivery bottlenecks. You must explicitly source profiles that handle data pipeline engineering and automated model evaluation.

The Core Profiles

  • AI Architect: Designs the systemic blueprint, foundation, and core framework.
  • AI Engineer: Builds individual agent use cases and orchestrates logical steps.
  • Data Engineer: Prepares, vectors, and securely routes internal enterprise data (RAG).
  • AI QA/Evaluation Engineer: Builds regression testing workflows to monitor agent accuracy.

Concept 4: Agent Orchestration Frameworks (LangGraph)

Status: 🟢 Understand the concept

What is it?

A software framework that provides a standardized structure for mapping out an agent's complex multi-step reasoning processes, actions, evaluations, and logic loops.

Why care as a DM?

Without an orchestration framework, developers write bespoke, messy "if/else" code. While it might work for 1 or 2 use cases, it creates massive technical debt and will completely stall a project trying to scale to 20+ use cases.

Delivery Takeaway (The Reasoning Loop)

The framework acts like a programmatic workflow where the agent executes an action, evaluates the output against business rules, and dynamically decides whether to proceed to the next step or deliver the final response to the user.

Simple Analogy

Building 20 custom lego sets without a framework is like dumping loose bricks on the floor with no manuals. Using a framework is like giving every developer the exact same base grid plate—the designs can be unique, but the foundation is uniform and predictable.
